# 08_ข้อผิดพลาดและการกู้คืน — WM-Core_801
Error Handling & Recovery Protocol  
โปรโตคอลการตรวจจับ–รับมือ–กู้คืนความผิดพลาดของระบบ WM-Core_801

---

## 1) ระดับความผิดพลาด (Error Levels)
ระบบ WM-Core_801 แบ่งความผิดพลาดออกเป็น 3 ระดับชัดเจน:

### **ระดับ 1 — Minor Error**
- ผลกระทบ: ไม่มีผลต่อระบบหลัก  
- ตัวอย่าง: ฟอร์แมตข้อมูลผิดรูปแบบ, metadata ไม่ครบ  
- ระบบจะ:
  - แจ้งเตือนผู้ใช้แบบ non-blocking  
  - แก้ไขอัตโนมัติ (auto-correction) ถ้าเป็นไปได้  
  - บันทึกลง Log

---

### **ระดับ 2 — Operational Error**
- ผลกระทบ: งานที่ทำอยู่ต้องหยุดหรือทำซ้ำ  
- ตัวอย่าง:  
  - AI ตีความไม่ได้  
  - IO Channel รับข้อมูลไม่สำเร็จ  
  - Task Dispatcher แยกงานผิดประเภท  
- ระบบจะ:
  - หยุด task ปัจจุบัน  
  - แจ้งผู้ใช้ + แนะนำทางแก้  
  - ส่งรายการเข้าสู่คิว retry  
  - บันทึกลง Log พร้อม error code  
  - ถ้า retry 3 ครั้งยังไม่ได้ → escalate ไป Custodian

---

### **ระดับ 3 — Critical / Security Error**
- ผลกระทบ: อาจกระทบข้อมูล, ความปลอดภัย, หรือโครงสร้างระบบ  
- ตัวอย่าง:  
  - ความผิดปกติของข้อมูล (tampered data)  
  - ละเมิด PDPA / Metadata loss  
  - ระบบไม่สามารถตรวจสอบตัวตนได้  
  - ความผิดปกติของ Core Processor  
- ระบบจะ:
  - หยุดงานทันที (system halt)  
  - แยกข้อมูลเข้าโหมด quarantine  
  - แจ้ง Custodian แบบ real-time  
  - ตรวจสอบย้อนกลับตาม Log ทั้งหมด  
  - รันระบบ *self-diagnosis* 24 ชม.

---

## 2) แหล่งกำเนิดความผิดพลาด (Error Sources)
ความผิดพลาดมาจาก 5 ชั้นหลัก:

1) Input Layer → ค่าผิดรูปแบบ / ไม่มี metadata  
2) Interpretation Layer → ไม่เข้าใจ intent / emotion  
3) Core Processor → task splitter ทำงานผิด  
4) IO Engine → ส่งออกข้อมูลไม่ได้  
5) System Layer → สิทธิ์การเข้าถึง / PDPA / token หมดอายุ  

ทุกข้อจะถูกผูกกับ:
- user_id  
- error_code  
- timestamp  
- task_id  

---

## 3) กลไกการตรวจจับ (Detection Mechanisms)

ระบบต้องตรวจจับอัตโนมัติด้วย 4 วิธี:

### **1) Validation**
- ตรวจความถูกต้องของ input ทุกชนิด  
- ถ้า metadata ไม่ครบ → reject ทันที

### **2) Confidence Check**
- ถ้า AI confidence < 0.45 → ถือว่า fail  
- ส่งกลับ Interpretation Layer ใหม่

### **3) SystemLog Analyzer**
- System Log จะตรวจจับรูปแบบผิดปกติ เช่น  
  - event ซ้ำ  
  - payload แปลก  
  - การเข้าถึง IO ผิดทาง

### **4) Security Scanner**
- ตรวจ PDPA  
- ตรวจ hash SHA-256  
- ตรวจ token  
- ตรวจความผิดปกติของบัญชีผู้ใช้

---

## 4) กลไกการกู้คืน (Recovery Protocol)

### **1) Soft Recovery (ระดับ 1–2)**
- retry task ใหม่  
- ทำ data cleansing  
- รีเซ็ต workflow เฉพาะบล็อกที่ผิดพลาด  
- แจ้งผู้ใช้พร้อมคำอธิบาย

### **2) Hard Recovery (ระดับ 3)**
- หยุด pipeline ทั้งหมด  
- แยกข้อมูลเป็น quarantine zone  
- ส่งสรุป error ให้ Custodian ตรวจสอบ  
- ตรวจสอบ Log 90 วันย้อนหลัง  
- เช็ค system checkpoint ล่าสุด  
- รีสตาร์ท Core Processor ด้วยโหมดปลอดภัย (Safe Mode)

---

## 5) ระบบแจ้งเตือน (Alerting System)
ระบบต้องมีช่องทางแจ้งเตือนดังนี้:

- แจ้งผู้ใช้ธรรมดา → banner / popup  
- แจ้ง Operator → task panel  
- แจ้ง Custodian → real-time alert (critical only)

รูปแบบแจ้งเตือนต้องมี:
- error_code  
- event  
- timestamp  
- user  
- suggestion  
- fallback link  

---

## 6) การบันทึก Log (Error Logging Rules)
ทุก error ต้องถูกบันทึกภายใต้มาตรฐาน:

- `ERROR_START`  
- `ERROR_CODE`  
- `ERROR_CONTEXT`  
- `AFFECTED_TASK`  
- `SYSTEM_CHECKPOINT`  
- `ERROR_END`  

เก็บรักษา ≥ 90 วันตามมาตรฐานเดิม
